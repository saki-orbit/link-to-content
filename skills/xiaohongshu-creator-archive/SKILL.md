# 小红书博主全量归档

用户给出小红书博主主页链接或作品链接时使用。用户只需要提供链接和归档偏好；默认处理主页中可访问的全部作品，不抽样，不让用户逐条复制作品链接。

## 默认交付

在当前项目旁建立“小红书归档/<博主名>/”目录，按作品保存：

- 每篇作品一个独立目录。
- `metadata.json` 使用统一字段：`title`、`platform`、`source_url`、`creator`、`published_at`、`duration_seconds`、`language`、`engines`。未知字段设为 `null`。
- 视频：`transcript.md` 逐字稿与 `subtitles.srt` 字幕。
- 图文：`ocr.md`，按图片顺序整理识别出的文字。
- index.csv 索引和失败清单。

转写优先使用本机模型，避免把整段音视频发给云端转写服务。Agent 只用识别后的文字做整理。

## 执行方式

开始处理前检查本 Skill 需要的本机工具；缺少时运行本目录下的 scripts/setup.sh，完成后继续，不要求用户手动配置模型。

1. 若用户给的是博主主页，使用本机已配置的小红书链接桥/API 获取公开作品分享链接。主页批量抓取需要小红书登录态；本机链接桥读取其配置的登录态。批量流程针对请求和采集做了优化，以降低账号风险；为稳妥起见，建议使用小号。单条作品链接不需要登录。不要只取首屏或前几条。
2. 规范化并去重链接，保留每条作品的标题和顺序。抓取失败的链接留在失败清单，不能悄悄略过。
3. 先收集链接和元数据。把所有视频链接放进一个清单，再调用 `multi-platform-media-transcript` Skill 的 `scripts/process_media.py` 一次批量转写；不要逐条运行，也不要读取逐字稿全文。脚本缺失时才沿用本 Skill 的本地转写流程。
4. 文章和图片继续使用现有读取与 OCR 能力。不要把整段媒体上传给云端转写服务。
5. 保留逐字稿原意，不凭空补全听不清的内容。可疑片段标记为“听不清”，而不是猜词。
6. 完成后报告发现、成功、失败数量和总输出目录。只在有失败时查看批次摘要中的失败项；不读取成功项的全文。

除非用户另行要求，不生成长篇分析，不改写原稿，不上传作品或逐字稿到飞书。
